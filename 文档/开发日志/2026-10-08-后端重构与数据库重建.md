## 一、为什么先做这件事

原计划是"完善 AI 助手模块"，实际讨论后调整为：**规范 → 结构 → 数据库 → 原型收尾 → 模块开发**。

理由：数据库是唯一"改起来最贵"的东西（代码可随时重构，schema 有数据后要写迁移脚本），
而且它是所有模块的共同依赖。趁现在无数据、无业务逻辑，改造成本最低。

## 二、后端包结构重构（三阶段）

### 2.1 阶段 A：按模块移动包

原先的包结构是**混合式**（最糟的组合）：`ai/`、`auth/`、`user/` 按功能分，
而 `entity/`、`mapper/`、`controller/`、`config/` 又按层分。

统一为**按功能模块分包，模块内再分层**。共移动 34 个文件：

| 原位置 | 新位置 | 数量 |
|--------|--------|------|
| `entity/` | 按模块拆到 `{user,note,knowledge,ai}/entity/` | 13 |
| `mapper/` | 同上拆到 `{...}/mapper/` | 13 |
| `config/` | `framework/config`、`framework/storage`(MinIO)、`framework/cache`(Redis) | 6 |
| `controller/HealthController` | `framework/health/` | 1 |
| `user/dto/UserProfileDTO` | `user/vo/` | 1 |

**关键实现方式**：不是手写映射，而是**由文件路径自动推导全限定名**，
并按长度降序替换（避免 `com.notemind.entity.Note` 误伤 `com.notemind.entity.NoteUser`）。

**顺带修正的配置**：
- `@MapperScan("com.notemind.mapper")` → 改为显式列出 4 个模块的 mapper 包
- `type-aliases-package: com.notemind.entity` → 改为 4 个模块的 entity 包

> **一个踩坑**：`type-aliases-package` 第一次没改成功。原因是 PowerShell 的 `-match` 默认
> **不区分大小写**，而正则里的 `$` 锚点在 CRLF 行尾（`\r`）前不匹配。
> 后改用 `\b` 词边界才生效。**教训：改配置文件后必须回读确认，不能只看命令没报错。**

### 2.2 阶段 B：类重命名

让代码名与新表名对齐（MyBatis-Plus 的驼峰转下划线正好自动对应）：

| 原类名 | 新类名 | 原表名 | 新表名 |
|--------|--------|--------|--------|
| `NoteUser` | `SysUser` | `note_user` | `sys_user` |
| `Notebook` | `NoteNotebook` | `notebook` | `note_notebook` |
| `Folder` | `NoteFolder` | `folder` | `note_folder` |
| `DocumentSource` | `KnowledgeDocument` | `document_source` | `knowledge_document` |
| `Conversation` | `AiConversation` | `conversation` | `ai_conversation` |
| `Message` | `AiMessage` | `message` | `ai_message` |
| `UserProfileDTO` | `UserProfileVO` | — | — |

共 17 个类（含对应 Mapper）+ 6 个表名 + 13 个文件重命名。

> **残留检查的误报**：检查脚本报了 13 处"残留"，实际全是假阳性 ——
> 因为 PowerShell 的 `-match` 不区分大小写，`\bMessage\b` 把 `Result.message`、
> `@NotBlank(message=...)` 都匹配上了。改用 `[regex]::IsMatch`（默认区分大小写）后确认**零残留**。
>
> **这条也说明：小写 `message` 绝不能跟着改** —— 它是注解属性、响应字段、
> `Throwable.getMessage()`，改了会破坏 API 契约与参数校验。

**顺带修正的字段名**：`SysUserMapper noteUserMapper` —— 类型改了但字段名没改，
已统一为 `sysUserMapper`。

## 三、错误码体系重构

### 3.1 问题

原先用 `BusinessException(400, "用户名已存在")` 与 `(400, "旧密码错误")` ——
**两个完全不同的失败原因共用一个 400**，前端无法区分，日志也定位不到模块。

### 3.2 新设计：HTTP 状态码与业务码分离

```java
public enum ErrorCode {
    PARAM_INVALID(1001, 400, "参数校验失败"),
    UNAUTHORIZED(1002, 401, "未登录或登录已过期"),
    FORBIDDEN(1003, 403, "没有访问权限"),
    RESOURCE_NOT_FOUND(1004, 404, "资源不存在"),
    SYSTEM_ERROR(1005, 500, "服务器内部错误"),
    METHOD_NOT_ALLOWED(1006, 405, "请求方法不支持"),
    // 2xxx 用户与认证
    USERNAME_EXISTS(2001, 400, "用户名已存在"),
    LOGIN_FAILED(2002, 401, "用户名或密码错误"),
    ...
}
```

- **HTTP 状态码**表达协议语义（401/403/404/400/500）
- **业务码**精确定位原因，按模块分段（1xxx 通用 / 2xxx 用户 / 3xxx 笔记 / 4xxx 知识库 / 5xxx AI）

**前端约定同步**：控制流一律依赖 **HTTP 状态码**，业务码只用于展示与按需分支 ——
避免前端把 `1002`、`2001` 这类数字写成魔法值散落各处。

### 3.3 过程中修掉的两个真实问题

**① 安全层的业务码与业务层不一致**

`RestAuthenticationEntryPoint` 手写 JSON 时传的是 HTTP 状态码 401，
而业务层抛 `ErrorCode.UNAUTHORIZED` 给的是 1002 —— 同一语义两种业务码。
已统一为从 `ErrorCode` 取值（401→1002、403→1003）。

**② 不存在的路径返回 500 而非 404**

Spring MVC 抛出的 `NoResourceFoundException` 被兜底的 `Exception` 处理器捕获，
于是"客户端请求了不存在的地址"被报成"服务端内部错误"，会误导排查方向。
已补上 `NoResourceFoundException`(404)、`HttpRequestMethodNotSupportedException`(405)、
`HttpMessageNotReadableException`(400) 三个处理器。

## 五、发现的两个真实 bug（本轮最有价值的部分）

### 🔴 bug 1：`TIMESTAMPTZ` 与 `LocalDateTime` 不匹配（运行时才炸）

把数据库时间字段改成 `TIMESTAMPTZ` 后，注册与登录**都返回 500**：

```
org.apache.ibatis.executor.result.ResultMapException:
  Error attempting to get column 'created_at' from result set.
  Cause: PSQLException:
    Cannot convert the column of type TIMESTAMPTZ to requested type java.time.LocalDateTime
```

**原因**：MyBatis 的 `LocalDateTimeTypeHandler` 调 `rs.getObject(col, LocalDateTime.class)`，
而 PG 驱动不会把 `timestamptz` 转成 `LocalDateTime`（它对应 `OffsetDateTime`）。

**迷惑性**：`mvn compile` 通过、应用能正常启动、日志无任何警告，
**只在真正读取该字段时报错**。

**修复**：15 个文件、29 处 `LocalDateTime` → `OffsetDateTime`；
同时**移除全部 23 处 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`** ——
该 pattern 不含时区偏移，前端 `new Date("2026-10-08 22:05:20")` 会按浏览器本地时区解析，
跨时区必然错。改用 Jackson 默认的 ISO-8601（`2026-10-08T22:05:20+08:00`），可被 `new Date()` 正确解析。

> **教训：数据库类型与 Java 类型必须成对修改。这条已写入《04-数据库设计规范》2.1 节。**
> **另：格式化是前端的展示职责，接口只负责传无歧义的值。**

### 🔴 bug 2：不存在的路径返回 500

见 3.3 ②。虽然后果比 bug 1 轻，但"客户端错误被报成服务端错误"会**误导排查方向**。
