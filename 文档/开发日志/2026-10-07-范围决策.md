# 开发日志：范围决策——明确不做 Agent

> 日期：2026-10-07

## 背景

项目在此前一个月处于停滞状态。原因是录制前端演示视频时，重新对照了三个参考对象（Obsidian、ima、Claudian 插件），发现实际体验远比预期复杂，进而怀疑"必须实现完整 Agent 才能做出 AI 对话"，产生"可能做不完"的判断。

## 本次结论

**NoteMind 不做 Agent。** 全部 AI 功能由"单次/多轮模型调用 + 检索增强（RAG）+ 结构化确认"实现。

关键澄清：此前把 5 件难度相差 10 倍的事混称为"Agent"：

| 被混称为 Agent | 实际 | 难度 |
|---|---|---|
| 多轮对话 | 持久化 + Prompt 组装 | ★ |
| SSE 流式 | fetch + ReadableStream | ★ |
| 思考链路 | API 的 `reasoning_content` 字段 | ★ |
| RAG | 检索管道（非智能体） | ★★★ |
| 建议→确认→写入 | 结构化输出 + 确认 + 应用 | ★★ |
| 真 Agent（工具循环） | — | ★★★★ |
| 多 Agent 编排 | — | ★★★★★ |

真正难的只有最后两项，而这两项**原方案本就排除**（[[方案定位]] 第 191 行"❌ AI Agent 自动执行"）。动摇的不是方案，是对方案的信心。

## 核实结果

### Claudian 是中间件，不是智能体实现

经核实（[YishenTu/claudian](https://github.com/YishenTu/claudian)），该插件自述"embeds AI coding agents (Claude Code, Codex CLI, …)"，要求本地安装至少一个 CLI harness，且标注 Desktop only；架构含 `core/process/`（子进程管理）、`providers/claude/`（Claude Agent SDK 适配器）、`providers/acp/`。

**结论：全部智能由第三方 CLI 提供，插件只做 UI + 进程管理 + 协议适配。** 因形态不符（Web 应用）、无技术内容可写、不可复现，不采用该路线；但其"供应商配置下放给用户"的思想已被原方案采纳。

### 思考链路的成本被高估

据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)，思考模式默认开启，思维链通过 `reasoning_content` 返回且支持流式。本项目实现成本仅为"多解析一个字段 + 多渲染一个可折叠区块"。

**同时发现的参数陷阱**：思考模式下 `temperature` / `presence_penalty` / `frequency_penalty` 传入不报错但不生效；`top_p` 仅在 `0.95–1.0` 有效。设置页需按模型区分可调项，否则用户调整静默失效。

### 架构收敛（本次最大收益）

原担忧"主页、笔记侧边栏、知识库三处都要知识库，工作量翻三倍"。实际是一个服务三种调用范围：

```
ChatService（唯一）
    └── RagService.retrieve(scope: NONE | KB | NOTEBOOK | NOTE)
            ├── 主页通用对话   (NONE)
            ├── 主页绑定知识库 (KB)
            ├── 笔记侧边栏     (NOTEBOOK / NOTE)
            └── 知识库问答     (KB)
```

这正是论文中"笔记与知识库融合架构"的落地形态，同时降低了实现量与论述复杂度。

## 新发现的问题（待处理，属代码层）

| 问题 | 位置 | 影响 |
|---|---|---|
| Prompt 占位符不一致 | `init.sql` 用 `{content}`，设计文档用 `{selection}` | 8 个预设快捷指令会把字面量 `{content}` 发给模型，**静默失效** |
| API Key 泄露 | `application.yml` 硬编码真实密钥，已入 Git 历史 | **需吊销密钥**并改环境变量 |
| 数据库配置三方不一致 | `application.yml` / `application-dev.yml` / `docker-compose.yml` 的库名与密码互不相同 | 部署必然失败 |
| 依赖缺失 | `pom.xml` 无 pgvector、无 `tika-parsers-standard-package` | 向量检索与 PDF/Word 解析均不可用 |
| Spring AI 版本 | `1.0.0-M6`（里程碑版） | 应升级至 1.0.x GA |
| 模型名不一致 | `application.yml` 为 `deepseek-v4-flash`，文档为 `deepseek-chat` | 需以控制台模型列表统一 |
| 新用户无初始化数据 | `init.sql` 种子数据仅关联 `user_id = 1` | 新注册用户登录后无默认笔记本、无预设快捷指令 |
