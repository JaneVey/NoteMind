# AI 供应商接入设计

> 设计模式：策略模式（基于 Spring AI 统一抽象）
> 目标：支持多供应商无感切换，用户可自由选择 AI 后端
> 最后更新：2026-07-20（重构后更新）

### 重构说明

原始方案采用手写策略模式（`AiProvider` 接口 + 各供应商实现）。

重构后基于 **Spring AI** 框架：
- 不再手写 `AiProvider` 接口，直接用 Spring AI 的 `ChatModel` / `EmbeddingModel`
- Spring AI 内置 OpenAI、Anthropic Claude、Google Gemini、Ollama 等供应商支持
- SSE 流式输出由 Spring AI 原生处理
- 减少重复代码，降低维护成本

## 3. 供应商支持计划

| 供应商 | ChatModel | EmbeddingModel | 说明 |
|--------|-----------|---------------|------|
| **DeepSeek** | `OpenAiChatModel`（兼容 OpenAI API） | `OpenAiEmbeddingModel` | 主要使用，性价比高 |
| **OpenAI** | `OpenAiChatModel` | `OpenAiEmbeddingModel` | 备选 |
| **Gemini** | `GeminiChatModel` | `GeminiEmbeddingModel` | Google 系，免费额度高 |
| Ollama（P2） | `OllamaChatModel` | `OllamaEmbeddingModel` | 本地私有化部署 |

### 关于 Claude

重构后**移除 Claude 支持**，原因：
1. Claude 的 API 格式不兼容 OpenAI（需要独立实现）
2. Claude 没有原生 Embedding API，需要额外搭配其他供应商
3. Gemini 的免费额度对学生更友好
4. 减少供应商维护数量，降低复杂度

如果后续需要 Claude，可以通过 Spring AI 的 `AnthropicChatModel` 重新加入。

### Embedding 模型备选

除供应商自带的 Embedding 模型外，也可对接：
- **BGE**（BAAI/bge-m3）— 开源中文 Embedding，可本地 / API 部署
- **Jina Embeddings** — 高性能，支持 8K+ 长文本，通过 `JinaEmbeddingModel` 接入

> 如果用户选择的供应商 Embedding 效果不理想，可以在设置中切换到备选 Embedding 供应商。

## 4. AI 配置管理

### 配置表结构

```java
@Entity
public class AiConfig {
    private Long id;
    private String providerName;      // deepseek / openai / gemini
    private String displayName;       // 显示名称
    private String apiKey;            // AES 加密存储
    private String apiBaseUrl;        // API 地址（可选）
    private String chatModel;         // 对话模型名
    private String embeddingModel;    // 向量化模型名
    private Boolean isActive;         // 当前激活
    private Integer sortOrder;        // 排序
}
```

### 动态切换机制

```java
@Service
public class AiConfigManager {

    private final Map<String, ChatModel> chatModelCache = new ConcurrentHashMap<>();
    private final Map<String, EmbeddingModel> embeddingModelCache = new ConcurrentHashMap<>();

    /**
     * 根据用户配置动态创建 ChatModel
     */
    public ChatModel getChatModel(AiConfig config) {
        return switch (config.getProviderName()) {
            case "deepseek", "openai" -> buildOpenAiChatModel(config);
            case "gemini" -> buildGeminiChatModel(config);
            default -> throw new UnsupportedProviderException(config.getProviderName());
        };
    }

    /**
     * 获取当前激活的供应商的 ChatModel
     */
    public ChatModel getActiveChatModel() {
        AiConfig active = aiConfigMapper.findByIsActive(true);
        return getChatModel(active);
    }
}
```

## 5. SSE 流式输出

### 后端（Spring AI 原生支持）

```java
@RestController
public class AIController {

    private final AiConfigManager aiConfigManager;

    @PostMapping("/api/ai/chat/stream")
    public SseEmitter streamChat(@RequestBody ChatRequest request) {
        SseEmitter emitter = new SseEmitter(0L); // 无超时

        ChatModel chatModel = aiConfigManager.getActiveChatModel();

        // Spring AI 流式调用
        Flux<ChatResponse> stream = chatModel.stream(buildPrompt(request));

        stream.subscribe(
            response -> {
                String content = response.getResult().getOutput().getContent();
                // 发送 SSE 事件
                emitter.send(SseEmitter.event()
                    .name("message")
                    .data(content));
            },
            error -> {
                emitter.completeWithError(error);
            },
            () -> {
                emitter.complete();
            }
        );

        return emitter;
    }
}
```

### 前端（EventSource）

```javascript
// utils/sse.js
export function createSSEConnection(url, body, {
  onMessage, onDone, onError
}) {
  const controller = new AbortController();

  fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
    signal: controller.signal
  }).then(response => {
    const reader = response.body.getReader();
    const decoder = new TextDecoder();

    function read() {
      reader.read().then(({ done, value }) => {
        if (done) { onDone?.(); return; }
        const text = decoder.decode(value);
        onMessage?.(text);
        read();
      });
    }
    read();
  }).catch(onError);

  return () => controller.abort(); // 返回取消函数
}
```

## 6. 对话流程

### 6.1 普通对话模式

```
用户输入消息
    │
    ▼
AIController.streamChat()
    │
    ├── 1. 查询当前激活的供应商配置
    │
    ├── 2. 构建 Prompt（系统提示 + 历史消息 + 用户画像 + 新消息）
    │       System: "你是 AI 助手...
    │                用户画像: {身份: 软件工程学生, 技术方向: Java后端}"
    │       User: "Spring Boot 怎么配置?"
    │
    ├── 3. ChatModel.stream(prompt)
    │       └── SSE 流式返回
    │
    ├── 4. 逐块推送到前端
    │
    └── 5. 完整消息接收后保存到 message 表
```

### 6.2 RAG 对话模式

```
用户输入问题
    │
    ▼
RagController.ask()
    │
    ├── 1. 查询绑定的知识库
    │
    ├── 2. EmbeddingModel.embed(question)
    │
    ├── 3. pgvector 检索相似块
    │       SELECT * FROM knowledge_chunk
    │       ORDER BY embedding <-> ? LIMIT 5
    │
    ├── 3.5 文本清洗（去除无关字符、统一格式）
    │
    ├── 4. 上下文组装
    │       System: "你是一个知识库助手...
    │                基于以下上下文回答问题，并标注引用来源。
    │
    │                ===== 上下文 =====
    │                来自 [Spring.pdf 第3章]:
    │                Spring 事务通过 AOP 代理实现...
    │
    │                来自 [Transaction.md]:
    │                声明式事务使用 @Transactional 注解...
    │                =================="
    │
    ├── 5. ChatModel.stream(prompt)
    │
    ├── 6. 回答 + 引用来源推送到前端
    │
    └── 7. 引用信息存入 message.metadata
```

## 7. 用户画像 / AI 记忆

### 设计方向

不做自动记忆，采用 **用户主动维护长期画像**。

用户可在设置页配置：

```
用户画像：
  身份: 软件工程学生
  技术方向: Java后端
  回答偏好: 简洁、技术细节优先
```

### Prompt 注入

```java
public Prompt buildPromptWithProfile(ChatRequest request, UserProfile profile) {
    String systemPrompt = """
        你是一个智能 AI 助手。
        
        == 用户画像 ==
        身份: %s
        技术方向: %s
        回答偏好: %s
        
        请根据用户画像调整回答风格。
        """.formatted(
            profile.getIdentity(),
            profile.getTechStack(),
            profile.getAnswerPreference()
        );

    return new Prompt(List.of(
        new SystemMessage(systemPrompt),
        new UserMessage(request.getContent())
    ));
}
```

## 8. Prompt 快捷指令

### 设计

用户自定义 Prompt 模板，集成到编辑器的右键菜单。

### 数据模型

```java
@Entity
public class PromptShortcut {
    private Long id;
    private String name;          // 显示名称（如 "论文降重"）
    private String prompt;        // Prompt 模板（使用 {selection} 占位符）
    private Integer sortOrder;
    private Boolean isEnabled;
}
```

### 执行流程

```
用户选中文字
    │
    ▼
右键 → "论文降重"
    │
    ▼
前端发送:
{
  "shortcutId": 1,
  "selectedText": "Spring Boot 是一个...",
  "contextNote": "# Spring Boot\nSpring Boot是一个..."
}
    │
    ▼
后端:
  PromptShortcut prompt = ...
  String fullPrompt = prompt.getPrompt()
      .replace("{selection}", selectedText)
      .replace("{context}", contextNote);
    │
    ▼
ChatModel.stream(new Prompt(new UserMessage(fullPrompt)))
    │
    ▼
SSE 返回结果
```

### Prompt 模板示例

```
论文降重:
  请降低以下内容的 AI 生成痕迹，使其更像人类写作风格：
  {selection}

代码解释:
  请用通俗易懂的方式解释以下代码：
  {selection}

翻译英文:
  将以下内容翻译为英文，保持技术准确性：
  {selection}

总结:
  请用 3-5 句话总结以下内容：
  {selection}
```

### 预设模板（系统初始化时自动创建）

| 名称 | 说明 |
|------|------|
| 解释 | 通俗易懂地解释选中内容 |
| 总结 | 简明扼要地总结选中内容 |
| 润色 | 优化语言表达和逻辑 |
| 扩写 | 在原有基础上扩展内容 |
| 翻译英文 | 翻译为英文 |
| 翻译中文 | 翻译为中文 |
| 继续写 | 基于选中内容继续往下写 |
| 论文降重 | 降低 AI 生成痕迹 |

## 9. 错误处理

| 错误场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| API Key 无效 | 捕获 401 | "API Key 无效，请检查配置" |
| 余额不足 | 捕获 402/429 | "API 调用次数已达上限，请检查账户余额" |
| 网络超时 | 重试 1 次后放弃 | "AI 服务连接超时，请检查网络" |
| 模型不存在 | 捕获 404 | "模型不存在，请检查模型名称" |
| Embedding 调用失败 | 返回空向量，降级为关键词检索 | "知识库检索降级为关键词模式" |
| Stream 中断 | 记录已收到的内容 | "连接中断，已保存部分回复" |
| 供应商切换失败 | 回退到上一个可用供应商 | "当前供应商不可用，已切换至..." |

## 11. 扩展性说明

### 添加新供应商只需：

1. 在数据库 `ai_config` 表插入一条配置
2. 如果 Spring AI 已支持该供应商：零代码，直接配置即可
3. 如果 Spring AI 不支持：实现 `ChatModel` / `EmbeddingModel` 接口

### 支持本地模型（P2）：

Spring AI 内置 Ollama 支持：

```
provider_name: ollama
api_base_url: http://localhost:11434
chat_model: llama3
embedding_model: nomic-embed-text
```

### 关于 Spring AI 版本提醒

Spring AI 目前仍在快速发展阶段（里程碑版本），API 可能会有变化。建议：
- 锁定具体版本号（如 `1.0.0-M6`）
- 在 Spring AI 外层封装一层业务接口，方便未来迁移
