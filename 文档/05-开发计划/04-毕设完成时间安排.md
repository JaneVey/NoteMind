## 二、核心策略

### 1. 错峰原则

```
9月-12月中：考证 + 秋招高峰 → 毕设只做低脑力碎片活
12月六级后-寒假：毕设主力期（约 2.5 个月空窗）
2月底-4月：论文 + 答辩
```

### 2. RAG 风险前置

RAG 是唯一"技术不确定"的模块（Embedding 服务、pgvector 检索效果、上下文组装），
**不能留到寒假才第一次碰**。11 月用低压力期先跑通"最小链路 demo"，把最大风险提前排掉。

### 3. 功能瘦身（保核心，砍边缘）

| 优先级 | 模块 | 说明 |
|--------|------|------|
| **P0 必须** | 笔记 + AI 助手 + 知识库/RAG + 用户系统 + 设置(模型配置) | 核心链路，论文创新点所在 |
| **P1 尽量** | 知识图谱、关键词搜索、Prompt 快捷指令 | 有富余就做 |
| **P2 砍掉** | OCR、历史版本、Word/PPT 上传(先 md+pdf)、头像、语义搜索、主题切换 | 答辩前若时间不够直接砍 |

> 论文和答辩只看核心链路（笔记 → 知识库 → RAG → 引用溯源），边缘功能不影响过。

## 三、阶段时间线

### 阶段 A：9月（启动期）— 碎片化铺垫

> 主旋律：软考冲刺 + 秋招投递。毕设只做"不需要调试、不依赖新知识"的活。

**目标**：把纯 CRUD 的后端接口补完，让"地基"完整。

| 任务 | 类型 | 耗时 |
|------|------|------|
| Notebook / Folder / Note 的 Controller + Service + DTO | 后端 CRUD | 碎片时间 2-3h/周 |
| Conversation / Message 基础 CRUD | 后端 CRUD | 碎片时间 |
| 读 Spring AI 官方文档（ChatClient / EmbeddingModel），收藏关键页 | 预热 RAG | 摸鱼时看 |
| 同步项目说明书到最新代码状态 | 文档 | 1h |

> 这些接口是纯 MyBatis-Plus CRUD，你熟，不需要大块调试，白天摸鱼/晚上顺手写。
> ⚠️ 注意：**9/17 软考报名截止、9月中六级报名**，别为了毕设错过报名。

---

### 阶段 B：10月（暂停期）

> 主旋律：软考（10/24-27）+ 秋招笔试面试高峰。

**毕设策略：完全暂停**，最多睡前看看 RAG 概念文章。
**原因**：这一个月是秋招黄金窗口，且软考在即，毕设硬挤两头都做不好。

---

### 阶段 C：11月（预热期）— RAG 最小链路 + AI 对话接口

> 主旋律：软考已过，六级还在强化期。毕设开始回温。

**目标**：解除 RAG 最大技术风险 + 把 AI 对话后端接通。

| 任务 | 说明 |
|------|------|
| AI 对话 SSE 接口（Spring AI ChatClient + 流式输出） | 纯对话，不接知识库 |
| Conversation / Message 完整 CRUD + 前端 AIChat 接入真实 SSE | 让 AI 助手真正能聊 |
| **RAG 最小链路 demo**（关键） | 上传 1 个 md → 分块 → Embedding → pgvector 检索 → 问答 |
| 评估：pgvector 检索效果 / Embedding 服务连通 / 分块策略初步验证 | 记录结论，寒假直接用 |

**RAG 最小 demo 验收标准**：
- [ ] 一个 Markdown 文档能入库
- [ ] 提问能检索到对应片段并返回回答
- [ ] 记录"分块多大、Top-K 多少"的初步调参结论

> 这块是毕设最硬的部分，**放在低压力期做，比寒假现学现做稳得多**。
> 时间投入：每周 4-6h（周末整块为主）。

---

### 阶段 D：12月中下旬 - 1月中（六级后）— 知识库 + RAG 产品化

> 主旋律：12/12 六级考完，秋招收尾。**毕设第一主力期。**

**目标**：知识库模块完整，RAG 从 demo 变成产品。

| 任务 | 说明 |
|------|------|
| KnowledgeBase CRUD + 文档上传（MinIO） | |
| 文档解析（md/pdf）+ 分块（复用 11 月结论） | |
| RagService 产品化：问题→Embedding→检索→上下文组装→LLM→SSE+引用 | 核心 |
| DocumentSource 处理状态管理（pending/processing/done/failed） | |
| 引用溯源（回答标注来源文档/章节） | 论文创新点 |
| 前端：KnowledgeBase.vue / DocumentList / DocumentUploader 接真实接口 | |

**时间投入**：每周 8-12h（晚上大块 + 周末）。这是今年最该投入毕设的一段时间。

---

### 阶段 E：寒假（1月中 - 2月中）— 攻坚收尾

> 主旋律：大四上学期结束，无课程，**全年最整块的时间**。

**目标**：全功能完成 + 可部署演示。

| 任务 | 说明 |
|------|------|
| 知识图谱：Wikilink 解析 + NoteLink + Graph.vue | P1 |
| 关键词搜索（PG ILIKE/tsvector） | P1 |
| Prompt 快捷指令 + 设置页面接接口 | P1 |
| Docker Compose 一键部署 + 演示数据 | P0 |
| 全链路联调：笔记→AI→导入知识库→RAG 问答→引用溯源 | P0 |
| 写 README / 部署文档 | P0 |

**时间投入**：每天 3-4h。**寒假结束 = 系统完整可演示**。

---

### 阶段 F：2月底 - 4月（大四下）— 论文 + 答辩

| 时间 | 任务 |
|------|------|
| 2月底-3月中 | 论文初稿（重点章节：RAG 引擎设计、融合架构、AI 辅助闭环、pgvector 语义检索） |
| 3月中-4月中 | 论文修改 + 查重 + 答辩 PPT + 演示视频/录屏 |
| 4月-5月 | 答辩 |

> **开发期同步攒论文素材**：每个模块写完后，把设计决策、难点、调参结论记进项目文档，别到最后补。

| 时段 | 毕设做什么 |
|------|-----------|
| 上班摸鱼 | ❌ 不适合写大段代码；✅ 适合看文档、理接口签名、读 RAG 资料 |

- 9-10月：晚上给软考/秋招，毕设只在摸鱼碎片做 CRUD

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| RAG 效果差 | 11 月预研跑通 + 分块/重叠/Top-K 调参，验证过再产品化 |
| 寒假时间不够 | 阶段 D 提前到六级后启动，别等寒假才开始 |
| 论文难写 | 开发中同步记录设计决策和调参结论，论文素材实时攒 |
| 秋招占用毕设时间 | 毕设是弹性项，但 12 月后是硬期限，靠阶段 D/E 自律执行 |
| 前端联调耗时 | 尽量后端先自测（Apifox），前端只做对接 |
