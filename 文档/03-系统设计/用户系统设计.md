# NoteMind 用户系统设计

> 从"单人固定 Token"升级为"完整用户系统"的决策记录。决定来源于 [[技术栈选型]] 中关于 Spring Security + JWT 的讨论。

## 决策背景

最初设计采用**单人模式 + 固定 Token**，原因是为了降低复杂度。后来经过重新评估，决定从第一版开始就引入完整用户体系。

**核心原因**：项目定位已从"交毕设"变为"毕设 + 长期维护 + 公网部署"，用户系统是后续所有扩展的基础。

## 数据库设计

### user 表

```sql
CREATE TABLE note_user (
    id          BIGSERIAL PRIMARY KEY,
    username    VARCHAR(100) NOT NULL UNIQUE,
    email       VARCHAR(255),
    password    VARCHAR(500) NOT NULL,   -- BCrypt 加密
    nickname    VARCHAR(100),
    avatar      VARCHAR(500),            -- MinIO 头像路径
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 所有业务表增加 user_id

| 表 | 新增字段 |
|----|---------|
| `notebook` | + `user_id` |
| `folder` | + `user_id`（或通过 notebook 间接关联） |
| `note` | + `user_id` |
| `knowledge_base` | + `user_id` |
| `document_source` | + `user_id` |
| `conversation` | + `user_id` |
| `ai_config` | + `user_id` |
| `prompt_shortcut` | + `user_id` |
| `user_profile` | 改为和 `note_user` 合并或用 `user_id` 关联 |

## 架构原则：用户与业务解耦

### 推荐做法

```
Controller 层：
    Long userId = LoginUser.getId();    // 从 Security 上下文获取
    noteService.getUserNotes(userId);   // 只传 userId

Service 层：
    只关心 userId，不关心 JWT、登录、Security
```

### 模块边界

```
com.notemind
├── auth            // 登录认证（JWT + Security 配置）
├── user            // 用户信息 CRUD
├── note            // 笔记（只通过 userId 关联用户）
├── knowledge       // 知识库
├── ai              // AI 助手
├── common          // 公共模块
├── config          // 配置
└── framework       // Security、JWT 等基础设施
```

### 杜绝的做法

```java
// ❌ 错误：业务层直接依赖 Security 工具类
public List<Note> getMyNotes() {
    Long userId = SecurityUtils.getUserId();  // 业务层不应该知道 Security
    return noteMapper.selectByUserId(userId);
}

// ✅ 正确：由 Controller 传入 userId
public List<Note> getUserNotes(Long userId) {
    return noteMapper.selectByUserId(userId);
}
```
