# 基于 RAG 的 NoteMind 智能知识管理平台

## 项目详细说明书

> 项目名称：基于 RAG 的 NoteMind 智能知识管理平台设计与实现  
> 项目类型：Java Web 全栈 AI 应用  
> 文档版本：V1.0  
> 编制时间：2026 年 8 月

## 一、项目概述

### 1. 项目背景

在学习、课程设计、科研阅读和求职准备过程中，个人会积累大量 Markdown 笔记、PDF 资料、Word 文档、课件和网页摘录。这些资料通常分散存放，存在以下问题：

1. 笔记工具便于记录，但难以针对大量历史资料进行语义检索和问答。
2. 通用 AI 对话工具可以回答问题，但不了解用户自己的笔记和资料，回答缺乏个人知识上下文。
3. 普通文档问答系统通常只提供“上传 - 问答”能力，无法承接日常知识创作、整理和关联。
4. AI 生成的回答往往缺少来源，用户难以判断内容依据，也不便于回到原文继续学习。

NoteMind 面向上述问题，设计一个将“笔记创作、资料管理、智能检索、AI 辅助写作和知识关联”整合在一起的个人知识管理平台。

### 2. 项目目标

系统以 Web 形式提供服务，用户可以在同一平台完成笔记编写、资料上传、知识库构建和 AI 问答。项目的核心目标如下：

- 支持用户通过 Markdown 笔记沉淀个人知识，并按笔记仓库和目录进行管理。
- 支持将 PDF、Word、PPT、Markdown 等资料导入知识库，建立可检索的向量索引。
- 基于 RAG 技术，让 AI 在用户自己的资料范围内回答问题，并提供回答引用来源。
- 将 AI 对话、选区处理、内容润色和直接修改笔记等能力融入写作过程。
- 通过双向链接和图谱展示笔记之间的关联，帮助用户发现知识结构。

### 3. 项目定位

NoteMind 不是单纯的 Markdown 编辑器，也不是普通 AI 聊天页面，而是一个以个人知识沉淀为基础、以 RAG 检索增强为核心、以 AI 辅助创作为扩展的智能知识管理平台。

系统中各部分的职责如下：

| 部分   | 主要职责                       |
| ---- | -------------------------- |
| 笔记   | 创建、编辑、分类和沉淀个人知识            |
| 知识库  | 解析资料、建立索引、提供语义检索           |
| AI   | 基于用户问题和检索内容进行辅助整理、分析、生成和问答 |
| 知识图谱 | 展示笔记间的链接关系和知识结构            |

## 二、总体设计

### 1. 系统架构

系统采用前后端分离的单体架构。单体架构能够降低部署、调试和联调复杂度，更适合个人毕业设计的开发规模；同时通过清晰的 Controller、Service、Mapper 分层，为后续扩展保留空间。

```text
Vue 3 前端
  ├─ 笔记编辑与目录管理
  ├─ AI 对话与流式消息展示
  ├─ 知识库、文档管理与引用展示
  └─ 知识图谱与系统设置
          │ HTTP / SSE / JWT
          ▼
Spring Boot 后端
  ├─ Controller：REST 接口和 SSE 接口
  ├─ Service：笔记、会话、RAG、文档处理等业务逻辑
  ├─ Security：Spring Security + JWT 认证鉴权
  ├─ AI：Spring AI 统一模型调用与 Embedding 接入
  └─ Mapper：MyBatis-Plus 数据访问
          │
          ├─ 数据与向量检索服务：业务数据、知识块与相似内容召回
          ├─ Redis：会话上下文与热点数据缓存
          └─ MinIO：原始文档、图片等对象存储
```

### 2. 技术选型

| 层次    | 技术方案                               | 选型说明                        |
| ----- | ---------------------------------- | --------------------------- |
| 后端    | Java 17、Spring Boot 3、MyBatis-Plus | 保持清晰的分层结构，适合快速实现业务接口        |
| 安全    | Spring Security、JWT、BCrypt         | 实现登录认证和多用户资源隔离              |
| 前端    | Vue 3、TypeScript、Vite、Pinia        | 组件化页面开发，TypeScript 降低接口对接错误 |
| AI    | Spring AI、DeepSeek/OpenAI/Gemini   | 统一模型调用接口，支持流式输出与供应商切换       |
| 存储与缓存 | MinIO、Redis                        | 管理原始文件、缓存会话上下文和常用数据         |
| 文档处理  | Apache Tika、CommonMark             | 解析多格式文档与 Markdown 内容        |
| 通信与部署 | SSE、Docker Compose、Nginx           | 流式展示 AI 回复，支持容器化一键部署        |

## 三、功能模块详细说明

### 1. 用户与权限模块

该模块提供注册、登录、个人信息维护和密码修改等功能。密码使用 BCrypt 加密后存储；登录成功后签发 JWT，前端在后续请求中携带 Token，后端通过过滤器完成身份解析。

业务数据均与用户关联，后端不信任前端传入的用户标识，而是从认证上下文中取得当前用户 ID，再执行资源查询和操作，从而降低越权访问风险。

### 2. 笔记管理模块

笔记模块参考 Obsidian 的知识管理方式，采用“笔记仓库 - 文件夹 - 笔记”三级组织形式。用户可按 Java 学习、毕业设计、求职准备等不同主题建立独立仓库。

主要功能包括：

- 笔记仓库的创建、修改、删除和排序。
- 多层文件夹的创建、重命名、移动和删除。
- Markdown 笔记的创建、编辑、删除、置顶和搜索。
- Markdown 所见即所得编辑、代码块和图片插入。
- 当前笔记上下文 AI 对话、选中文本快捷操作及 AI 修改建议回写。
- 将笔记或文件夹内容加入知识库，形成“创作 - 检索 - 问答”的联动。

前端笔记页采用目录树、编辑器、AI 侧边栏的三栏布局。该页面不仅涉及普通表单交互，还需解决编辑器状态同步、自动保存、目录切换、AI 流式展示和内容回写等问题。

### 3. AI 助手模块

AI 助手提供独立于笔记的通用对话入口，支持新建对话、历史会话管理、收藏、重命名和删除。一个会话可以按需绑定某个知识库，绑定后默认使用该知识库进行 RAG 检索。

系统通过 SSE 将模型回复以分片形式实时返回前端。前端需要持续累积并渲染回复内容；后端需要在流式结束后保存完整消息、Token 使用量和引用信息。针对连接中断，需要保留已接收文本并给出明确提示。

用户还可维护个人画像，例如身份、技术栈和回答偏好。系统在构建 System Prompt 时将这些信息作为可控上下文注入，以提升回答的个性化程度。

### 4. 知识库与文档处理模块

知识库用于集中管理可供 AI 检索的资料。用户可创建多个知识库，例如“Java 知识库”“毕业设计资料库”“论文资料库”，不同知识库之间的数据相互隔离。

文档导入流程如下：

```text
选择文件
  -> 文件上传至 MinIO
  -> 提取文档文本
  -> 按规则进行文本分块
  -> 调用 Embedding 模型生成向量
  -> 保存知识块、来源信息并建立检索索引
  -> 更新文档处理状态
```

模块支持展示文件名称、类型、大小、上传时间、解析状态及失败原因，并提供预览、删除和重新解析操作。文档处理使用 `pending`、`processing`、`done`、`failed` 四种状态，便于前端反馈处理进度和排查错误。

### 5. RAG 智能问答模块

RAG 是本项目的核心技术模块。它不直接把用户问题发送给大模型，而是先从用户知识库中查找语义相关的文本片段，再将这些片段与问题共同发送给模型，从而使回答尽量依据用户已有资料。

基本流程如下：

```text
用户提问
  -> 对问题进行 Embedding
  -> 在指定知识库中执行向量 Top-K 检索
  -> 过滤低相关知识块并控制上下文长度
  -> 组装 System Prompt、检索上下文和用户问题
  -> 调用大语言模型并通过 SSE 返回回答
  -> 保存消息、检索来源和引用信息
```

为提升回答可信度，系统不会只返回 AI 文本，而是同时展示引用的资料来源，例如文档名称、页码、章节或相关内容片段。用户可以通过引用回到原始资料继续核查。

### 6. 知识图谱与搜索模块

用户可以在笔记中使用 `[[笔记标题]]` 创建双向链接。后端在笔记新增或更新时解析该语法，维护 `note_link` 关系表；前端通过图谱组件展示节点和边，并支持点击节点跳转至对应笔记。

搜索功能分为两类：

- 关键词搜索：通过全文检索或模糊匹配，快速查找标题和正文中的直接关键词。
- 语义搜索：对搜索问题进行向量化，查找语义相近的笔记或知识块，适合用户不知道精确关键词的场景。

## 四、核心流程与关键实现

### 1. 笔记到知识库的联动

项目不是把笔记和知识库简单并列，而是建立单向数据联动：笔记作为可编辑的原始知识，知识库作为可检索的处理后知识。用户可以选择笔记或文件夹加入知识库，系统将对应内容转换为知识块和向量索引。

这种设计使用户日常记录的内容可以自然进入后续问答流程，同时避免把知识库检索结果直接反向修改原始笔记，保证内容来源和编辑责任清晰。

### 2. AI 辅助写作流程

当用户在编辑器中选中文字并选择“解释”“总结”“润色”等快捷指令时，系统会将 Prompt 模板、选区内容和必要的笔记上下文组合后发送给模型。模型结果先展示给用户，再由用户确认是否写入笔记，避免 AI 自动覆盖原有内容。

该流程包括 Prompt 模板管理、选区内容获取、上下文长度控制、流式输出、Markdown 格式处理和编辑器回写等多个实现环节。

### 3. 引用溯源流程

文档解析时，系统为每个知识块记录其来源信息。RAG 检索命中知识块后，这些来源信息会随上下文传递到回答生成阶段；回答完成后，系统将引用整理为前端可展示的数据结构。

引用溯源使系统能够回答“该结论来自哪份资料、哪一页或哪一段”，增强问答结果的可核查性，也为后续检索效果评估提供依据。

项目工作量主要体现在多个模块的协同实现，而不是简单增加页面数量。系统需要完成需求分析、页面设计、前后端开发、AI 服务接入、文件处理、联调测试和部署文档等完整工程工作。

| 工作模块 | 主要工作内容 | 工作量特点 |
| --- | --- | --- |
| 基础与安全 | 工程脚手架、用户注册登录、JWT 鉴权、密码加密、统一异常处理 | 是所有业务模块的前置基础，需要同时处理前后端状态和权限隔离 |
| 笔记与目录 | 仓库、目录树、Markdown 编辑、自动保存、搜索、文件导入 | 编辑器与目录树交互复杂，需要处理内容状态和多种编辑场景 |

| 前端联调与体验 | 页面组件、状态管理、加载态、失败态、空状态、前后端联调 | 工作贯穿所有模块，决定系统能否形成完整可演示产品 |

## 六、项目创新点

### 1. 笔记创作与 RAG 知识库融合

项目将笔记系统和 RAG 知识库设计为两个职责不同但可联动的层次：笔记负责知识创建和维护，知识库负责解析、向量化和语义检索。用户的日常笔记可选择性进入知识库，形成“记录 - 沉淀 - 检索 - 问答”的完整闭环。

与单纯笔记工具相比，系统能够基于个人积累回答问题；与单纯文档问答工具相比，系统能够承接持续的知识创作和整理过程。

### 2. 面向写作过程的 AI 辅助闭环

项目将 AI 能力嵌入笔记编辑流程，而不是仅提供独立聊天窗口。系统同时支持当前笔记对话、选中内容快捷处理和 AI 建议回写三种方式，并允许用户自定义 Prompt 快捷指令。

用户可以将“总结”“润色”“扩写”“翻译”“代码解释”等操作配置为可复用模板，在编辑器内完成调用。通过“先展示建议、再确认写入”的方式，系统保留用户对原始笔记的控制权。

### 3. 可追溯的 RAG 问答设计

系统在知识块层面保存文档名、页码、章节等来源信息，并将命中来源与 AI 回答一起返回。用户不仅能获得结论，也能看到结论来自哪份资料、哪个位置。

该设计提升了 AI 问答的可信度和可核查性，尤其适用于论文资料、技术文档和课程笔记等需要回看原文的场景。

### 4. 可配置的多供应商 AI 接入

系统通过 Spring AI 抽象模型调用，支持配置不同供应商、模型名称、访问地址和参数。聊天模型与 Embedding 模型可分别配置，业务层不直接依赖具体供应商。

这一设计既避免厂商绑定，也让系统能够根据模型可用性、成本和效果进行切换。对于 API Key 无效、限流、超时、Embedding 失败等情况，系统设计了提示、重试或降级处理。

### 5. 轻量级双向链接知识图谱

系统使用 Markdown 的 `[[Wikilink]]` 语法建立笔记关联，并保存节点和边的关联关系。在不引入专门图存储组件的情况下，实现仓库范围内的关系查询与图谱可视化。

该方案兼顾了实现成本和展示效果，能够直观反映笔记之间的知识关联，并体现从文本编辑到结构化知识组织的扩展能力。

## 七、关键难点与应对方案

| 难点       | 应对方案                                          | 验证方式                |
| -------- | --------------------------------------------- | ------------------- |
| RAG 检索质量 | 控制分块长度和重叠、按知识库过滤、配置 Top-K、过滤低相关内容、控制上下文 Token | 使用固定问题集测试命中内容与回答相关性 |
| 流式会话一致性  | SSE 分片累积、前端实时渲染、结束后完整保存；中断时保留已接收文本            | 模拟网络中断，检查前端展示和消息保存状态 |
| 多用户资源隔离  | 由 JWT 获取当前用户，所有业务查询带 `user_id` 条件             | 多账号交叉访问测试，验证无越权读写   |
| 文档解析稳定性  | 使用状态机记录处理过程和错误信息，支持失败后重新解析                    | 上传正常、异常和不同格式文件进行测试  |
| 模型供应商差异  | 保持业务接口稳定，配置层管理供应商差异，必要时降级                     | 切换模型和无效配置场景测试       |

## 八、预期成果

项目完成后，将形成以下成果：

1. 可运行的 NoteMind Web 系统，支持笔记管理、AI 对话、知识库管理和 RAG 问答。
2. 完整的前后端源代码、部署配置和项目技术文档。
3. 基于 Docker Compose 的本地一键部署方案。
4. 具有引用来源展示的 RAG 问答演示数据和测试结果。
5. 笔记双向链接图谱、用户 Prompt 快捷指令等可演示特色功能。
6. 对应的系统设计、测试与论文材料。

## 九、总结

NoteMind 项目覆盖 Java Web 全栈开发与 AI 应用工程的关键环节，包含用户认证、笔记管理、对象存储、文档解析、SSE 流式通信、向量检索、RAG 问答、来源溯源和图谱可视化等内容。项目规模不是简单的 CRUD 系统，而是围绕个人知识管理场景构建一条完整的“知识沉淀 - 智能检索 - AI 辅助 - 来源核查”链路。

项目的重点不在于重复实现已有 AI 产品，而在于将笔记、知识库和 AI 能力进行合理融合，并通过可追溯问答、可配置 Prompt、多供应商接入和轻量级知识图谱等设计，形成一个适合个人学习和知识管理的完整系统。
